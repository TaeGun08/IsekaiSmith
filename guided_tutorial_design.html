가이드식 튜토리얼 기획서

guided_tutorial_design.html · tutorial_design.html(임시 슬라이드형)의 최종 형태로 교체

기존 TutorialUI는 "읽고 넘기는" 슬라이드였습니다. 이번엔 바닥에 네비게이션 화살표를 띄워서 다음에 어디로 가야 하는지 직접 유도하고, 실제로 그 행동을 완료해야 다음 단계로 넘어가는 방식으로 바꿉니다 - 설명을 읽는 게 아니라 몸으로 한 바퀴 돌면서 배우는 형태. TutorialUI의 슬라이드 로직은 걷어내고 이 시스템이 대체합니다.

1. 범위

이번에 포함

  • 단계별 목표를 화면 상단 배너로 표시 ("나무 4개 모으기" 등)
  • 목표 지점을 향한 바닥 화살표(플레이스홀더 지오메트리, 플레이어를 따라다니며 방향 갱신)
  • 실제 행동 완료를 감지해서 자동으로 다음 단계 진행(탭해서 넘기는 게 아님)
  • 최초 1회만 자동 진행, 완료 후 다시 안 뜸(PlayerPrefs)
  • 건너뛰기 버튼(급한 유저용)

이번엔 미룸

  • 사냥/전투 단계 안내 - 아직 그 시스템 자체가 없음
  • 화살표의 실제 경로탐색(NavMesh 기반 우회) - 지금 맵은 장애물이 거의 없어서 직선 방향 표시로 충분, 필요해지면 나중에 보강
  • 다국어 - 프로젝트 전체가 아직 영문 UI 기준(project_no_korean_font_yet)

2. 단계 시퀀스 - 실제 완료 조건 기준

0환영 - 풀스크린 카드 한 장(기존 TutorialUI 스타일 재사용), "시작하기"로 닫으면 1단계 진입. 화살표 없음.
1이동 - 화면 드래그로 이동 안내. 완료 조건: 플레이어가 처음 HasMovementInput이 true가 된 순간(한 번이라도 움직이면 통과).
2나무 모으기 - 화살표가 LumberCamp를 가리킴. 완료 조건: ResourceBank.Get(Wood)이 단계 진입 시점보다 4 증가(v1의 "1개면 통과"에서 상향 - 사용자 피드백: 1개는 채집했다는 실감이 안 남). 배너에 "(2/4)"처럼 실시간 진행도 표시.
3돌 모으기 - 화살표가 Quarry를 가리킴. 완료 조건: ResourceBank.Get(Ore)이 4 증가(나무와 동일 기준).
4제작 - 화살표가 Smithy를 가리킴. 완료 조건: ToolInventory.Total이 처음 증가한 순간(QUICK CRAFT 버튼 눌러도 통과).
5판매 - 화살표가 SalesCounter를 가리킴. 완료 조건: 첫 TryFulfill 성공(SalesCurrency.Gold 증가 감지).
6완료 - "이제 자유롭게 플레이하세요!" 짧은 토스트 후 배너/화살표 전부 숨김, 다시 안 뜸.

2~5단계는 "탭해서 다음" 이 아니라 실제 조건 충족을 매 프레임 감지해서 자동 전환 - 배너에는 진행 중인 목표만 뜨고, 완료되면 짧은 완료 표시 후 바로 다음 화살표로 전환.

3. 화면 구성

4. 화살표 구현 방식

지오메트리플레이스홀더 수준 - 실제 화살표 스프라이트/모델 대신 납작한 삼각형(Cone 프리미티브를 눕혀서) 여러 개를 점선처럼 배치하거나, 단순하게 화살촉 모양 하나만 플레이어 앞 2~3유닛 지점에 띄워서 목표 방향으로 회전시키는 쪽으로 단순화(구현 시 더 가벼운 쪽 선택).
추적 로직매 프레임 목표위치 - 플레이어위치 방향으로 Quaternion.LookRotation, 화살표는 플레이어보다 살짝 앞/위(바닥에서 뜬 높이)에 위치시켜 항상 시야에 들어오게 함.
목표 지점단계별로 이미 씬에 있는 실제 오브젝트 참조 - 벌목장/채석장/대장간/ 판매대. 별도 웨이포인트 배치 불필요(전부 이미 존재).

5. 구현 메모

  • 클래스 - GuidedTutorial.cs 신규(Assets/01. Scripts/UI/). 기존 TutorialUI의 슬라이드 진행 로직(Next/Skip 다단 카드)은 걷어내고, 0단계 환영 카드만 남긴 뒤 이 클래스가 이어받는 구조로 재편. ResourceHUD.Start()의 부트스트랩 호출 대상만 교체.
  • 완료 감지 - 각 단계가 "이전 프레임 값 대비 증가했는가"를 폴링하는 방식(기존 ResourceHUD의 lastX 패턴과 동일 스타일) - 새 이벤트 시스템 도입 없이 일관성 유지.
  • 대상 오브젝트 참조 - 벌목장/채석장/대장간/판매대를 GameObject.Find 또는 직렬화 필드로 참조. 씬에 이미 있는 오브젝트라 새 배치 작업 불필요.

6. 확인 결과 반영됨

  • Q1 → 답변: 기준을 올림. §2 완료 조건을 "1개면 통과"에서 나무/돌 각 4개로 상향 - 구현 완료(WoodGatherTarget/OreGatherTarget = 4, 배너에 실시간 진행도 표시).
  • Q2 → 답변: 제안한 순서(단순하게 시작 → 부족하면 보강) 그대로 진행. 지금은 단순 화살촉 플레이스홀더 그대로 유지 - 실플레이해보고 부족하면 점선 경로로 보강 예정(아직 착수 안 함).

별다른 이견 없으시면 이 값들로 바로 구현 들어가겠습니다.

7. 세분화 개정 v1.1 - 실플레이 피드백

실제 구현을 보니 "벌목장으로 가라"는 뭉뚱그린 안내가 아니라, 나무 한 그루 → (캐면) 보관함 순서로 하나씩 짚어주는 게 맞다는 피드백. 확인해보니 벌목장/채석장의 나무·광물은 TreeFieldSpawner/ResourceFieldSpawner가 씬 시작 시 런타임으로 흩뿌려 생성하는 것이라 고정된 오브젝트를 미리 참조할 수 없고, 보관함(StorageDepot)은 벌목장/채석장이 아니라 대장간 안(StorageCrate1=나무, StorageCrate2=광물)에 있다는 것도 확인함(왕복 동선). 이 두 가지를 반영해서 채집 단계를 아래처럼 쪼갭니다.

2-1나무 캐기 - 화살표가 매 순간 가장 가까운 살아있는 WoodNode를 가리킴(고정 오브젝트가 아니라 런타임 탐색). 완료 조건: 짊어진(아직 미예치) 나무가 4개(CarryStack.GetCount(Wood) >= 4).
2-2나무 옮기기 - 화살표가 대장간의 StorageCrate1을 가리킴. 완료 조건: ResourceBank.Get(Wood) 증가(자동 예치 감지).
3-1돌 캐기 - 가장 가까운 살아있는 OreNode 추적. 완료 조건: 짊어진 광물 4개.
3-2돌 옮기기 - 화살표가 StorageCrate2를 가리킴. 완료 조건: ResourceBank.Get(Ore) 증가.
4제작 - 화살표가 대장간을 가리킴. 배너 문구에서 CRAFT(정밀 - 미니게임, 더 좋은 품질)와 QUICK CRAFT(즉시 제작) 둘 다 있다는 걸 명시적으로 안내. 완료 조건은 기존과 동일하게 ToolInventory.Total 증가(어느 쪽을 선택해도 통과) - 둘 다 강제로 시켜보게 할지는 아래 Q3 참고.

가장 가까운 대상 탐색은 FindObjectsByType<WoodNode>/ <OreNode>로 매 프레임 재계산(밭 규모가 작아 성능 문제 없음) - 캐던 나무가 쓰러지면(IsAvailable == false) 자동으로 다음으로 가까운 나무를 가리키게 됩니다.

8. 추가 확인 부탁드립니다

  • Q3. §7-4 제작 단계 - CRAFT/QUICK CRAFT 중 아무거나 하나만 하면 통과로 둘까요, 아니면 QUICK CRAFT 먼저 시켜보고 나서 "이번엔 CRAFT로 직접 만들어보세요"처럼 두 번 다 경험시킬까요? (후자가 더 친절하지만 튜토리얼이 한 단계 더 늘어남)
  • Q4. 캐기 목표 개수 4개 - 나무/돌 공통으로 유지해도 될까요, 아니면 등급별 재고 쌓아두는 느낌을 살리게 대장간 첫 제작 레시피 요구량(오레 2 + 나무 1)에 맞춰 더 낮출까요?

확인 주시면 바로 구현 들어가겠습니다.
