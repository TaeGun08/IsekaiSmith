손님 주문(판매) 시스템 기획서

customer_order_design.html · game_design_doc.html §5/§6/§7/§10을 실제 구현 상태에 맞춰 구체화

핵심 루프(§1)의 "사냥→보관→제작"까지는 이번에 완성됐고, 다음은 "판매→골드→재투자" 차례입니다. 기존 기획서(game_design_doc.html)는 손님 주문의 큰 그림만 있었는데, 이번 문서는 지금 실제로 구현된 것(ResourceType, CraftGrade 7단계, ResourceBank)을 전제로 바로 만들 수 있는 수준까지 구체화합니다.

1. 이번 범위 - 어디까지 하고 어디는 미룰까

이번에 포함

  • 골드 시스템 (신규 - 지금 프로젝트엔 화폐 개념이 아예 없음)
  • 등급별 재고 관리 (완제품을 등급 구분 없이 개수로만 세던 것 보완)
  • 손님 주문 큐(대기줄) + 주문서 UI + 인내심 게이지
  • 납품 처리 + 지급액 계산(등급 기본가 + 속도 보너스)
  • 평판 시스템(주문 실패 시 판매 수익 % 감소)

이번엔 미룸 (나중 별도 작업)

  • 손님 3D 캐릭터/워크 애니메이션 - 이번엔 주문서 UI 큐로만 표현 (§3 참고)
  • 암시장 상인(§5, 재료 매입/매출) - 판매 루프가 먼저 자리잡은 뒤
  • 필드/스테이지/던전 사냥터 확장, 전투 - §2/§9, 별도 라운드
  • 대장간 성장(시각적 재투자) - §8, 맵 디자인 영역이라 범위 밖
  • 무기/도구 종류 다양화 - 지금은 검(Tool) 하나뿐이라 주문도 "Tool + 최소 등급"까지만

2. 구조적으로 먼저 풀어야 하는 문제 - 등급별 재고

지금 ResourceBank는 완제품(Tool)을 등급 구분 없이 그냥 개수로만 셉니다. 그런데 손님 주문은 "강철 등급 이상"처럼 최소 등급 조건이 있어야 재미있는 시스템이라(game_design_doc.html §6), 지금 구조로는 "내가 가진 Tool 3개 중 어떤 게 Masterwork이고 어떤 게 Rough인지" 구분이 안 됩니다.

그래서 재료용 ResourceBank와는 분리된, 완제품 전용 ToolInventory를 새로 둡니다 - 등급별로 개수를 세는 아주 작은 클래스입니다(예: Rough 2개, Fine 5개, Superior 1개...). 아이템 하나하나에 고유 ID나 실제 스탯을 붙이는 "진짜 인벤토리 시스템"까지는 아직 안 가고, 딱 주문 매칭에 필요한 만큼만 확장합니다 - 모듈화 원칙대로 재료 은행과 완제품 재고는 성격이 다르니 억지로 한 클래스에 합치지 않습니다.

기존ResourceBank.Get(ResourceType.Tool) - 등급 무관, 그냥 총 개수
변경 후ToolInventory.Get(CraftGrade grade) - 등급별 개수 / ToolInventory.TrySpendAtLeast(CraftGrade minGrade) - 조건을 만족하는 가장 낮은 등급부터 소모(고등급은 더 좋은 주문을 위해 아껴둠)

3. 손님 표현 방식 - 이번엔 "주문서 큐"로 단순화

실제 손님 캐릭터가 거리에 나타나 걸어와서 줄을 서는 것(game_design_doc.html 원안)은 캐릭터 애니메이션/경로탐색이 새로 필요해서 범위가 커집니다. 이번 1차는 판매대 근처에 서면 뜨는 "주문서 큐" UI로 손님을 대신합니다 - 로직(등급 매칭, 인내심, 지급액, 평판)은 완전히 동일하고, 나중에 손님 캐릭터를 추가할 때도 이 로직은 그대로 재사용하고 겉모습만 캐릭터로 바꾸면 됩니다.

4. 주문 흐름

일정 주기로
주문서 생성
→
큐에 대기
(최대 N개)
→
인내심 감소
(등급 높을수록 김)
→
납품 or 시간초과
  • 주문 생성 - 판매대 근처에 있을 때 일정 주기(예: 20~40초 랜덤)로 새 주문서가 큐에 추가됩니다. 큐가 가득 차면(예: 최대 4개) 새 주문이 더 안 생깁니다.
  • 등급 조건 - "이 등급 이상"으로 판정합니다. 강철 주문에 미스릴을 납품하면 받아주되 등급 초과분 보너스는 없음(재고 관리 실수 여지를 줄이기 위함, game_design_doc.html §6 그대로 계승).
  • 인내심 - 등급이 높은 주문일수록 인내심 시간이 깁니다(어차피 그만큼 만드는 데 오래 걸리니까). 시간 초과 시 주문서가 사라지고 평판이 깎입니다.
  • 납품 - 주문서를 탭하면 ToolInventory.TrySpendAtLeast(minGrade)로 조건을 만족하는 가장 낮은 등급부터 자동 소모하고 즉시 골드 지급.

5. 지급액 계산

기본가 (등급별)Rough 10G / Common 16G / Fine 24G / Superior 36G / Exceptional 54G / Masterwork 80G / Legendary 150G - 실제로 납품한 아이템의 등급 기준으로 지급(주문이 요구한 최소 등급이 아니라, 실제로 건넨 물건의 등급).
속도 보너스남은 인내심 비율에 비례해 최대 +50% 추가 (인내심 가득 찬 상태에서 바로 납품하면 최대 보너스, 거의 다 되어갈 때 납품하면 보너스 거의 없음).
평판 배율§6의 평판 게이지가 최종 지급액에 곱해짐 (100%=정상, 60%=수익 -20%).
최종 공식지급액 = 기본가(등급) × (1 + 속도보너스) × 평판배율

기본가 수치는 초기값이라 실제 플레이해보고 조정합니다(자동 생산/즉석 제작으로 쉽게 나오는 Fine 이하와, 수동 제작으로만 나오는 Superior 이상 사이에 확실한 소득 차이를 두는 게 목표).

6. 평판 시스템

  • 시작값 100%. 주문을 놓치면(시간 초과) 일정량 감소(예: -8%p), 연속 성공하면 서서히 회복(예: 성공 3회당 +2%p).
  • 게임오버 없이 "요즘 장사가 잘 안 된다"는 체감으로만 이어지는 가벼운 페널티 (game_design_doc.html 확정 사항 그대로).
  • 하한선을 둬서(예: 최소 40%) 한 번 크게 미끄러져도 회복 불가능한 상태로는 안 빠지게 합니다.
