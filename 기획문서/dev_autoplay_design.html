개발자 자동 플레이 모드 기획

dev_autoplay_design.html · 테스트용 봇 설계

채집→보관→제작 루프를 매번 손으로 반복하지 않고, 특히 등급 RNG 분포와 이번에 넣은 풀링/훅 시스템의 회귀 여부를 빠르게 확인하기 위한 개발자 전용 자동 플레이 봇입니다. 출시 빌드에는 절대 포함되지 않도록 처음부터 조건부 컴파일로 격리합니다.

한 사이클이 끝나면 다시 목표 선정으로 돌아가 반복 - 완전 자율 루프

2. 목표 우선순위

  • 등에 짊어진 광물/목재가 가득 찼다 → 가장 가까운 보관함으로 이동해 예치
  • 제작에 필요한 재료(광물 2 + 목재 1)를 이미 보유 중이다 → 대장간으로 이동해 제작
  • 그 외 → 가장 가까운 미채집 나무/광석 중 하나로 이동해 채집

이동은 새 로직을 만들지 않고 실제 플레이어와 똑같이 PlayerMotor.SetKeyboardInput()에 목표 방향 벡터를 밀어넣는 방식으로 처리합니다. 이동/충돌/카메라 관련 버그도 같은 경로로 같이 검증됩니다.

3. 제작 자동화 범위

A. 즉석 제작(QUICK CRAFT)만 자동화

추천

CraftingStation에 테스트 전용 훅 TryDevQuickCraft() 하나만 추가해서 QUICK CRAFT 경로를 트리거합니다. 미니게임 로직 자체는 건드리지 않고, 자원 경제/등급 확률/풀링 회귀를 빠르게 대량으로 검증하는 데 집중합니다.

B. 미니게임까지 자동 플레이

풀무질 홀드-릴리즈 타이밍, 망치 클릭 타이밍까지 흉내내는 시뮬레이션 로직이 별도로 필요합니다. 구현 비용이 높은데, 미니게임 자체의 손맛 검증은 어차피 사람이 직접 해봐야 해서 지금 당장의 이득은 적습니다. 필요해지면 나중에 추가.

4. 켜고 끄는 방식

A. 화면 구석 토글 버튼

추천

좌상단에 작은 "AUTO PLAY" 버튼. 터치로 켜고 끌 수 있어서 실기기 개발 빌드에서도 확인 가능합니다 - 모바일 게임이라 결국 기기에서도 검증해야 하니 처음부터 이 방식이 낫습니다.

B. 에디터 전용 키 단축키

예: F9. 구현은 더 간단하지만 에디터 안에서만 쓸 수 있고, 빌드된 기기에서는 켤 방법이 없습니다.

5. 로그 & 통계

매 제작마다 등급/수량을 콘솔에 로그로 남기고, N회마다 등급 분포 요약(Rough~Legendary 각각 몇 번 나왔는지)을 찍어서 확률 밸런스를 눈으로 확인할 수 있게 합니다.

AUTO PLAY: ON
[12] Craft -> Fine x1
[13] Craft -> Superior x2
[14] Craft -> Rough x1
--- 50 crafts: Rough 9 / Common 14 / Fine 15 / Superior 8 / Exceptional 3 / Masterwork 1 / Legendary 0 ---

화면 좌상단 토글, 노란 점 = 봇 목표 이동 경로, 하단 로그 박스에 최근 결과 + 주기적 등급 분포 요약

6. 빌드 격리

조건부 컴파일#if UNITY_EDITOR || DEVELOPMENT_BUILD로 클래스 전체를 감싸서 출시 빌드에는 코드 자체가 포함되지 않게 합니다.
기본 상태토글은 항상 OFF로 시작 - 실수로 켜진 채 플레이하는 일이 없도록.
씬 배치기존 UI 싱글톤들과 같은 패턴 - 별도 씬 배치 없이 최초 접근 시 자체 생성.
