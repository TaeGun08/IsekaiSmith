몬스터 다양화 - 역할별 AI

monster_variety_design_v1.html · combat_design_v1.html의 공통 전투 기반(체력/피격 연출/상태이상)은 그대로 두고, 몬스터 "종류" 축을 신설 (사용자 요청 2026-08-24)

배경. 지금은 Monster 클래스 하나가 필드 잡몹부터 스테이지 몹, 던전 몹/보스까지 전부 담당하고, SetStrength(hpMult, dmgMult) 배율로만 세기를 조절합니다. 종류가 하나뿐이라 콘텐츠도 단조롭고, 밸런스도 "하나의 공식 × 배율"로만 조절되어 세밀하게 잡기 어렵습니다 (스테이지1 웨이브1에서 몬스터 3마리가 동시에 몰려오면 최대 체력 100을 넘는 피해를 줄 수 있음을 확인 - 이번 작업에서 같이 잡습니다). 최적화(몬스터 풀링 등)는 이번 범위 밖 - 다양화가 끝난 뒤 별도로 진행합니다.

1. 아키텍처

Monster는 공통 기반(체력/사망 처리/피격 플래시/피격 상태이상 - Fire/Poison/Lightning/Frost를 "맞는" 쪽)으로 남기고, 접근·공격 방식만 protected virtual 훅으로 분리해서 역할별 서브클래스가 오버라이드합니다. 외부에서 몬스터를 만드는 곳(FieldMonsterSpawner/StageEncounterController/ DungeonEncounterController, 총 4곳의 Monster.Spawn 호출)은 새 팩토리 MonsterFactory.Spawn(MonsterRole role, position, parent)로 교체 - SetStrength/SetTint/ SetScale/SetAlwaysAggro 등 기존 외부 API는 그대로 유지되어 호출부 나머지 로직은 거의 안 건드립니다.

전부 SetStrength의 hpMult/dmgMult가 이 기본값 위에 그대로 곱해집니다 - 필드/스테이지/ 던전이 쓰는 기존 배율 스케일링 방식은 안 바뀝니다.

3. 신규 매커니즘

  • Projectile - 런타임 생성 구체가 몬스터→플레이어 직선으로 날아가 도착 시 PlayerHealth. TakeDamage 판정 (다른 클래스들처럼 코드로만 생성, 프리팹 없음).
  • 플레이어 슬로우 디버프 - PlayerMotor에 speedMultiplier + ApplySlow(duration, multiplier) 신설. Monster가 Frost를 맞으면 스스로 느려지는 것과 대칭 구조 - 이번엔 몬스터가 플레이어에게 거는 버전.
  • 지원형 버프 - Monster에 임시 damageBuffMultiplier 필드 추가, Support가 주변을 스캔해서 걸어줌 - 접촉/투사체 데미지 계산에 곱해짐.

4. 배치 - 어디에 어떤 역할이 나오는가

장소구성
필드(상시 잡몹)근접만 - 튜토리얼 난이도 그대로 유지
스테이지 1웨이브1 근접만(하향된 수치), 웨이브2 엘리트를 탱커로 교체
스테이지 2근접 + 원거리 혼합
스테이지 3근접 + 원거리 + 마법 혼합, 엘리트 = 탱커
던전층이 깊어질수록 5종 전부 등장 확률 상승, 보스 = 탱커 베이스 + 스케일업(기존 구조 유지)

5. 진행 순서

  1. Monster 리팩터(공통 기반 + virtual 훅) + MonsterFactory + MonsterRole enum
  2. 5개 역할 서브클래스 구현 (근접부터 - 기존 동작 그대로 이전 + 밸런스 하향)
  3. Projectile, PlayerMotor 슬로우, Support 버프 매커니즘
  4. 4개 스폰 호출부(필드/스테이지/던전 몹·보스)를 팩토리+배치표대로 교체
  5. 컴파일/한 사이클 검증 후 커밋
  6. (별도 후속) 최적화 패스
