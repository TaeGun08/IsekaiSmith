AI Companion - 에셋 패키징 & 셋업 마법사 기획

aicompanion_asset_packaging_design_v1.html · IsekaiSmith 전용 도구 → 이식 가능한 범용 에셋

지금 Assets/01. Scripts/Editor/AiCompanion에 있는 AI Companion 도구를 다른 프로젝트에도 폴더 하나 복사만으로 바로 붙는 독립 로컬 UPM 패키지로 재구성합니다. Unity MCP 패키지나 각 Provider CLI(Claude/Codex/Cursor)가 대상 컴퓨터에 없을 때는, 실패하고 끝나는 게 아니라 자동 설치 버튼 또는 가이드 안내를 보여주는 셋업 마법사를 새로 만듭니다.

1. 현재 상태 진단

항목현재 상태이식 시 문제
코드 위치 Assets/01. Scripts/Editor/AiCompanion/** (asmdef 없음) 이 프로젝트의 "01. Scripts" 폴더 관례에 종속 → 다른 프로젝트 구조에 끼워 넣으면 뒤섞임
Unity MCP 의존 UnityMcpBridgeAccessor가 리플렉션으로 소프트 연결 - 없어도 컴파일/채팅 동작 이미 해결됨 - 그대로 재사용
Provider CLI 설치 CliInstaller + OfferInstall이 메시지 전송 시점에 반응형으로 설치 제안 로직은 있음 - 셋업 마법사에서 그대로 재사용, 진입 시점만 추가
배경 이미지 CharacterStageElement.cs가 Assets/03. Art/Sprites/CompanionRoomBackdrop.png 경로를 하드코딩 이 프로젝트 전용 아트 파일 - 다른 프로젝트엔 없음(이미 null-가드는 있어 크래시는 안 남)
세션/로그 저장 Library/ClaudeCompanion/sessions.json (프로젝트 상대 경로) 경로 계산이 이미 상대적 - 손댈 필요 없음

2. 패키징 방식

로컬 임베디드 UPM 패키지

채택

Packages/com.taegun08.aicompanion/에 package.json + 전용 asmdef로 격리. 다른 프로젝트엔 이 폴더 하나만 복사하면 끝 - 대상 프로젝트의 Assets 구조를 전혀 건드리지 않음. Package Manager 창에 "In Project"로 정상 표시되고, 나중에 git 저장소로 옮기면 manifest.json에 URL 한 줄 추가하는 배포로도 자연스럽게 넘어감(Unity MCP 패키지 자체가 이미 이 방식).

.unitypackage 내보내기

더블클릭 임포트라 배포는 간단하지만, 지금처럼 Assets/01. Scripts/... 절대 경로를 그대로 가져가서 대상 프로젝트 폴더 관례와 충돌하기 쉽고, 업데이트 시 재임포트해도 옛 파일이 안 지워짐. asmdef 격리도 직접 챙겨야 해서 UPM 대비 이점이 없음.

package.json에는 Unity MCP를 강제 dependency로 넣지 않습니다 - 이미 소프트 의존(리플렉션)으로 설계돼 있는데 UPM 레벨에서 강제하면 "MCP 없이도 채팅은 된다"는 기존 설계와 모순되기 때문입니다. README에 "권장 설치"로만 안내하고, 실제 설치는 셋업 마법사의 버튼이 담당합니다.

git mv로 이동해 스크립트/uss의 .meta(=GUID)는 그대로 보존합니다. 폴더 자체의 .meta(옛 AiCompanion.meta, UI.meta)는 폴더 구조가 바뀌므로 새로 생성되게 둡니다. 배경 이미지는 이동하지 않고 지금 위치에 그대로 둔 채, 코드 쪽 하드코딩 경로를 AssetDatabase.FindAssets("CompanionRoomBackdrop t:Texture2D") 이름 기반 검색으로 바꿔서 이 프로젝트는 계속 배경이 보이고, 새 프로젝트는 파일이 없으니 기존 null-가드대로 무배경으로 동작합니다.

점검 항목

  • Unity MCP 패키지 (선택) - 없으면 채팅은 되지만 에디터 조작 툴콜 비활성 자동 설치
  • Node.js / npm - CLI 설치의 전제조건, 런타임 자체 설치는 위험해서 안내만 가이드
  • Claude CLI 자동 설치
  • Codex CLI 자동 설치
  • Cursor CLI - 공식 설치가 curl|bash라 자동화 불가 가이드

Unity MCP 설치는 UnityEditor.PackageManager.Client.Add(...)로, CLI 설치는 기존 CliInstaller.InstallNpmPackageAsync를 그대로 재사용합니다(새 로직 중복 없음). 메인 창의 반응형 설치 제안(OfferInstall)은 그대로 남겨둬서, 마법사를 닫고 나중에 실제로 메시지를 보낼 때도 안전망은 유지됩니다.

5. 범위 밖

  • UI 텍스트 로컬라이즈 - 지금 모든 라벨이 한국어 하드코딩. 에디터 도구라 게임 내 폰트 제약과는 무관하지만, 영어권 재사용을 원하면 별도 작업.
  • macOS/Linux 설치 스크립트 - CliInstaller가 cmd.exe를 직접 호출해 Windows 전용. 크로스플랫폼 npm 설치 지원은 이번 범위 밖.
  • git 원격 배포(URL 설치) - 이번엔 로컬 임베디드 패키지까지만. 별도 저장소로 분리해 manifest.json git URL 설치를 지원하는 건 다음 단계.
