손님 주문(판매) 시스템 기획서 v2

customer_order_design_v2.html · v1(customer_order_design.html)의 §3~5를 "밀려오는 카운터"로 개정 · §2/§6은 v1 그대로 유지

v1은 로직(등급 매칭/인내심/지급/평판)은 맞게 짰지만, 손님을 "스크롤되는 주문서 목록"으로만 표현해서 실제로 플레이해보면 손님 접객보다는 할 일 목록을 처리하는 느낌에 가까울 수 있습니다. 버거플리즈/피자레디/XP히어로처럼 "쉴 틈 없이 카운터가 채워지는" 리듬을 참고해서 §3(표현), §4(생성 흐름), §5(지급액)를 손봤습니다. 3D 손님 캐릭터를 새로 만드는 게 아니라, 같은 주문서 UI를 운영하는 방식만 바꾸는 것이라 범위는 v1과 거의 동일합니다.

1. 참고작에서 뽑아낸 것 - 캐릭터가 없어서가 아니다

세 게임 다 손님을 풀 3D 워크 애니메이션으로 구현하지 않습니다 (버거플리즈/피자레디는 카운터에 고정된 2D 아이콘 + 말풍선, XP히어로도 손님이 화면 안에서 상시 오가는 정도). 즉 이미 v1이 하려던 "주문서 UI" 수준의 표현 난이도와 같습니다 - 문제는 캐릭터 유무가 아니라 운영 방식이었습니다.

버거플리즈 / 피자레디

손님이 카운터 자리에 항상 서 있고, 한 명이 떠나면 즉시 다음 손님이 그 자리를 채웁니다. 화면이 절대 비지 않음 - "대기줄에 쌓인다"가 아니라 "자리가 계속 채워진다".

XP히어로

손님(모험가) 방문이 파도처럼 몰렸다 뜸해지는 구간이 있어 리듬감이 생깁니다. 균일한 간격 생성보다 훨씬 "장사가 잘 될 때/한산할 때"가 체감됨.

공통

연속으로 빨리 처리할수록 콤보/보너스가 붙어서, 플레이어가 스스로 "밀려오는 걸 쳐내는" 손맛을 만들어냅니다.

v1 진단: ① 슬롯 개념 없이 스택에 쌓이기만 함 (자리가 안 채워짐, 그냥 리스트) → 고정 카운터 슬롯 + 즉시 재보충 (§3)
② 생성 간격이 항상 균일(20~40초 랜덤) (파도가 없어 밋밋함) → 혼잡 웨이브 주기 도입 (§4)
③ 빨리 처리해도 보상 차이가 속도보너스뿐 (연타할 이유가 약함) → 콤보 보너스 추가 (§5)

2. 등급별 재고 - ToolInventory v1과 동일

v1 §2 그대로 진행합니다. 재료용 ResourceBank와 분리된 완제품 전용 ToolInventory(등급별 개수, 조건 만족하는 최저 등급부터 소모)를 신설합니다. 자세한 내용은 customer_order_design.html §2 참고.

3. 손님 표현 방식 개정 - 스크롤 목록 → 고정 카운터 슬롯

여전히 3D 캐릭터/워크 애니메이션은 만들지 않습니다. 대신 주문서를 세로로 쌓이는 목록이 아니라, 항상 정해진 개수만큼 나란히 보이는 "카운터 슬롯"으로 바꿉니다. 슬롯마다 손님을 상징하는 작은 아바타(직업군 힌트 컬러의 원형 아이콘 - 모험가/ 기사/마법사 등, 실제 캐릭터 모델은 아님)를 붙여 "티켓"이 아니라 "손님이 서 있다"는 인상을 줍니다.

슬롯 개수고정 3슬롯. v1의 "큐 최대 4개" 개념을 대체 - 큐에 쌓아두는 게 아니라 자리 자체가 3개뿐입니다.
재보충슬롯이 비면(납품 완료 또는 시간 초과) 1~2초 뒤 자동으로 다음 손님이 등장. 빈 슬롯이 오래 비어있지 않도록 해서 화면이 늘 "장사 중"으로 보이게 함.
등장 연출새 주문서가 슬롯에 나타날 때 pop-in(스케일 0→1 바운스) + 효과음 큐 - "누가 도착했다"는 신호를 명확히 (구현 시 추가, 이 문서는 로직 범위).

4. 주문 흐름 개정 - 웨이브 페이싱

슬롯 비면
1~2초 뒤 재보충
→
인내심 감소
(등급 높을수록 김)
→
납품 or 시간초과
→
슬롯 다시 비움
기본 재보충 지연슬롯이 빈 순간부터 1~2초 랜덤 후 새 주문 등장 (v1의 "20~40초마다 생성"을 대체 - 이제 생성 주기는 슬롯 회전 속도에 자연히 종속됨).
혼잡 웨이브60~90초마다 한 번, 8~12초짜리 "RUSH" 구간 발생. 이 구간에는 재보충 지연이 1~2초 -> 0.3~0.6초로 줄어 손님이 몰아쳐 오는 느낌을 만듭니다. 웨이브가 아닌 평소 구간은 오히려 "한산한" 체감을 주기 위해 그대로 둡니다.
등급 조건 / 인내심 / 납품v1 §4와 동일 (이 등급 이상 판정, 등급 높을수록 인내심 김, ToolInventory.TrySpendAtLeast(minGrade)로 최저 등급부터 자동 소모).

5. 지급액 계산 개정 - 콤보 보너스 추가

기본가 / 속도 보너스v1 §5와 동일 (등급별 기본가, 남은 인내심 비례 최대 +50%, 실제로 납품한 아이템 등급 기준).
콤보 보너스 신규시간 초과 없이 연속 납품 성공할 때마다 콤보 +1. 콤보 3부터 지급액에 보너스 적용 - 콤보당 +5%p, 최대 +25%p(콤보 5 이상). 시간 초과(놓침) 시 콤보는 0으로 리셋.
평판 배율v1 §6과 동일 (100%=정상, 60%=수익 -20%).
최종 공식지급액 = 기본가(등급) × (1 + 속도보너스) × (1 + 콤보보너스) × 평판배율

콤보는 "빨리 여러 명 쳐내면 이득"이라는 동기를 줘서, RUSH 웨이브 구간에서 플레이어가 적극적으로 슬롯을 훑게 만드는 게 목적입니다. 수치는 초기값이라 플레이 후 조정.

6. 평판 시스템 v1과 동일

v1 §6 그대로 진행합니다 (시작 100%, 시간초과 -8%p, 성공 3회당 +2%p, 하한 40%). 다만 "성공 3회당 회복"의 3회 카운트는 콤보 카운트와는 별개의 누적치입니다(콤보는 연속이 끊기면 0으로 리셋되지만, 평판 회복 카운트는 끊겨도 유지) - 헷갈리지 않게 구현 시 두 카운터를 분리합니다.
