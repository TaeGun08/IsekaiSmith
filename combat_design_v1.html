전투/사냥터 시스템 기획서 v1

combat_design_v1.html · 신규 - game_design_doc.html §2/§9(전투 개념)의 방향을 실제 구현 가능한 1단계로 구체화. §9 자체가 "세부 수치는 별도 턴에서" 라고 명시해뒀던 부분.

남은 로드맵(사냥터/전투 · 재료·무기 다양화 · 해금 게이트 · 암시장) 중 전투를 가장 먼저 잡습니다 - 재료 다양화(광물 등급업)는 던전 클리어가 전제고, 해금 게이트는 스테이지/던전 존재가 전제라 나머지 전부가 전투 위에 얹히는 구조입니다. 암시장은 의존성이 없어 순서가 자유롭지만, 전투가 없는 상태에서 먼저 넣으면 "왜 존재하는지" 체감이 약해 뒤로 미룹니다.

1. 이번 범위 - 필드 전투 MVP

이번에 포함

  • 필드에 약한 잡몹(슬라임) 소수 상주 - §2 "전투 압박 거의 없음, 튜토리얼 성격"
  • 플레이어 체력 + 몬스터 접촉 시 피해
  • 근접 자동 전투 - 채집(도끼/곡괭이)과 동일하게 근처에 있으면 자동으로 스윙, 별도 공격 버튼 없음
  • 플레이어 사망 시 대장간 인근으로 리스폰(페널티 없음)
  • 체력 게이지 UI
  • v1.1 추가 필드 몬스터 처치 시 낮은 확률로 저품질 마석 드랍 + 목재/광물처럼 등짐 적재(§7)

다음 단계로 미룸

  • 스테이지(순차 웨이브)/던전(랜덤 생성) - §2의 나머지 2개 층. 실제 진입 방식(포탈? 메뉴?), 웨이브 구조, 랜덤 생성 알고리즘 전부 미정 - 별도 문서에서 다룰 규모
  • 마석 등급(세기)×속성(화염/독/번개/냉기) 체계 - 필드 드랍은 등급/속성 구분 없는 단일 "저품질" 카운트만(§7). 실제 등급×속성 인챈트는 스테이지 콘텐츠가 있어야 의미가 생김
  • 장착 무기 시스템("내가 만든 무기 장착") - 무기 다양화(②)가 먼저 있어야 "장착할 무기"가 여러 개 존재함. 이번 MVP는 §4의 임시 기본 공격력으로 대체
  • 몬스터 다양화(슬라임 외 종류) - 필드는 원래도 "잡몹 소수"라 1종으로 충분
  • 등짐 최대 적재량을 골드로 늘리는 업그레이드 - 이번엔 필드가 나오는 지점(자리)만 비워두고, 실제 상점/UI는 사용자님 지시로 착수(§7 하단 참고)

2. 재검토 결과 - 기획 누락/애매한 부분 + 제안

전체 기획서(game_design_doc.html)를 다시 훑으며 찾은, 아직 결정 안 된/빠진 부분과 제 제안입니다. 이견 없으시면 이 값들로 바로 구현합니다.

  • ①1 재투자 → "도구/대장간 확장"이 뭘 의미하는지 불명확. §1 핵심 루프에는 있지만 §8(대장간 성장)은 시각/맵 영역이라 범위 밖으로 빠져 있고, "도구 업그레이드" 자체는 어느 섹션에도 수치가 없음. → 제안: 이번 MVP에선 손 안 대고, ②(무기 다양화) 단계에서 자연스럽게 "더 좋은 도구=더 빠른 채집/전투"로 연결(광물 등급별 곡괭이/도끼도 매트릭스에 포함되어 있어 §3 참고).
  • ②1 전투 세부 수치가 기획서에 전혀 없음(§9가 스스로 "별도 턴에서" 라고 명시). → 이 문서 §3/§4에서 확정.
  • ③1 사망 페널티가 안 정해져 있음. → 제안: 게임오버/자원 손실 없이 HP 풀회복 + 대장간 인근 리스폰 + 짧은 무적시간만. 손님 주문 실패(§6)를 "평판 하락"이라는 부드러운 페널티로 처리한 것과 톤을 맞춤 - 이 게임은 지금까지 어디에도 강한 처벌이 없음.
  • ④1 몬스터 비주얼 자산이 없음. → 제안: 지금 프로젝트 전체가 그렇듯(플레이어=캡슐, 손님=캡슐, 자원=박스) 틴트된 구체 프리미티브로 슬라임 표현 - 코드로 직접 생성해서 씬/프리팹 배치 작업이 전혀 필요 없게(제 작업 범위가 "배치"가 아니라 "기능"이라는 원칙과도 맞음).
  • ⑤1 필드 몬스터의 보상이 안 정해져 있음. §2 표에는 필드의 "주 획득물"이 광물 뿐이고 몬스터 처치 보상은 언급이 없음. → 애초엔 "무보상 유지"로 제안했으나, 사용자 지시로 저품질 마석 드랍으로 확정(§7) - 마석을 어디서도 얻을 방법이 아예 없었던 공백을 필드 단계부터 채우고, 등급/속성 있는 "진짜" 마석은 여전히 스테이지 몫으로 남겨둠.

3. 몬스터 - 슬라임 (필드 잡몹)

체력30 (플레이어 기본 공격력 10 기준 3방)
접촉 피해5, 1.2초마다 1회(붙어있는 동안 계속)
추격(aggro) 반경4m - 이 안에 들어오면 플레이어를 향해 이동 시작
공격 반경1.2m - 이 안에 들어오면 멈추고 접촉 피해 틱
이동 속도1.8 (플레이어 기본 이동보다 느리게 - 도망 가능해야 "압박 거의 없음"에 맞음)
개체수/리스폰필드에 4마리 상주, 처치 후 8초 뒤 다른 위치에 재출현
등장 위치v1.1 수정 "왼쪽 벌목장 - 가운데 사냥터 - 오른쪽 채석장" 배치(사용자 확정) 기준, LumberCamp와 Quarry 두 오브젝트의 실제 위치 중점을 앵커로(좌표 임의 지정 아님) 반경 8m 안에 스캐터 - 두 채집지(44m 간격) 사이 정확히 가운데
비주얼초록 계열 틴트 Sphere(플레이어/손님과 같은 프리미티브 컨벤션), 맞으면 붉은색으로 짧게 플래시, 처치 시 살짝 찌그러졌다 사라지는 연출

4. 플레이어 전투

  • 자동 근접 공격 - 채집(PlayerWoodcutting/PlayerMining)과 동일 패턴: 몬스터가 공격 반경 안에 있으면 자동으로 주기적 스윙, 별도 입력 불필요(이 게임 전체가 지금까지 이 방식 하나로 일관됨).
  • 공격력 - 기본 10, 0.6초 주기. 아직 무기 다양화(②)가 없어 "장착 무기 등급"이라는 개념 자체가 없으므로 이번엔 고정값 - ②에서 장착 무기 시스템이 생기면 이 상수 하나만 "장착된 도구의 등급 기반 계산식"으로 교체(자리만 미리 비워둠).
  • 스윙 연출 - 아직 검 등 전용 무기 모델이 없어 기존 ToolSwing.PlayAxeSwing()을 임시로 재사용(§9 원문: "이미 구현된 도끼/곡괭이 스윙을 그대로 재사용"과 부합) - 실제 무기 비주얼은 ②에서 붙임.
  • 체력 - 최대 100. 몬스터 접촉 피해로만 감소(다른 위협 없음).
  • 사망 처리 - HP 0 도달 시: HP 풀회복 + 대장간(SalesCounter 인근)으로 순간이동 + 1.5초 무적(리스폰 직후 바로 다시 맞아 죽는 것 방지) + 골드/재료 손실 없음.

5. 구현 메모

  • 이 프로젝트의 기존 관례대로 전부 코드에서 자체 생성 - 씬/프리팹에 사람이 미리 배치해둘 게 없음(맵 배치는 사용자님 영역이라는 원칙과 일치). 몬스터 스포너는 GuidedTutorial처럼 Instance 자동 생성 싱글턴.
  • 몬스터 AI는 CraftingStation/StorageDepot 등 기존 상호작용 클래스들과 동일하게 매 프레임 거리 계산만으로 판정(콜라이더/트리거 불필요) - 이동까지 필요한 점만 다름.
  • PlayerHealth는 ResourceBank/Reputation과 같은 순수 정적(static) 클래스로 - HP는 UI가 매 프레임 읽어가는 값일 뿐, 자기 자신을 표시할 필요가 없는 데이터.
  • 체력 UI는 ResourceHUD의 씬 배선 텍스트에 새로 끼워넣지 않고(씬 편집 필요), InteractionPromptUI처럼 코드로 자체 캔버스를 만드는 소형 HP 바로 분리.

7. 마석 드랍 + 등짐 적재 v1.1 - 사용자 추가 요청

사용자 요청: "필드 몬스터에서 마석 엄청 품질이 낮은 마석을 얻을 수 있고, 마석은 통나무와 광석처럼 플레이어 등에 쌓이도록". §2 ⑤1에서 "무보상 유지"로 제안했던 부분을 이걸로 대체합니다.

드랍 확률처치 시 45% - 잡몹이 흔하고(4마리 상주, 8초 리스폰) 저품질이라는 설정상 트리클(찔끔찔끔) 정도로, 파밍 대상은 아니게
등짐 적재CarryStack에 CarryLayer.ManaStone 신설 - 목재/광물과 동일한 "캐면 등에 쌓이고, 보관함 근처에서 자동 예치" 흐름 그대로 재사용. 기본 적재 한도 6개(목재/광물의 8개보다 낮게 - "엄청 낮은 품질"이라는 설정에 맞춰 살짝 더 귀하게)
비주얼보라 계열 작은 큐브 조각 - 목재(등 뒤)/광물(등 위)과 겹치지 않게 플레이어 옆쪽에 별도 열로 쌓임
예치 장소신규 세 번째 보관함(StorageCrateMana) - 기존 나무/ 광물 보관함 두 개가 이루는 선을 그대로 연장한 자리에 정확히 배치(좌표를 임의로 정하지 않고, 두 기존 보관함의 실제 위치·간격에서 계산). 다른 두 보관함과 똑같이 근접 발판 (InteractionPadIndicator)도 자동으로 붙음

다음 예고 - 등짐 한도 골드 업그레이드: 사용자가 "나중에 최대 적재량을 골드로 늘릴 수 있게" 하고 싶다고 밝힘 - 이번엔 착수하지 않지만, CarryStack의 한도를 레이어별 단일 필드(manaCapacity 등)로 유지해둔 게 이 업그레이드의 자리를 미리 비워둔 것(나중에 이 값을 수정하는 상점 UI 하나만 추가하면 됨). 착수 시점은 사용자 지시 대기.

8. 다음 단계 예고
