손님 주문(판매) 시스템 기획서 v4

customer_order_design_v4.html · v1~v3의 "주문서 UI 큐" 표현 방식을 3D 손님으로 교체

실제로 플레이해보니 티켓 목록을 탭하는 방식은 "주문을 처리한다"는 느낌이지 "손님을 접객한다"는 느낌이 아니었습니다. 버거플리즈/피자레디, 그리고 "좋은 피자, 위대한 피자"처럼 손님이 직접 카운터로 걸어와 머리 위에 말풍선으로 주문을 띄우고, 그에 맞는 무기를 건네면 만족하고 돌아가는 방식으로 바꿉니다. v1의 원래 계획(손님 캐릭터)으로 되돌아가는 것이고, v1~v3에서 UI로 미뤄뒀던 부분만 이번에 채워 넣습니다 - 주문 로직(생성/인내심/지급액/평판)은 전부 그대로 재사용하고, "그 주문을 어떻게 보여주고 어떻게 납품받는가"만 바뀝니다.

1. 바뀌는 것 / 그대로인 것

그대로 (OrderQueueManager)슬롯 재보충 페이싱, 러시아워 웨이브, 인내심 감소, ToolInventory.TrySpendAtLeast 매칭, 지급액 공식, 평판 시스템 - 전부 customer_order_design_v3.html 그대로. 슬롯 인덱스가 이제 "몇 번째 대기 자리에 서 있는 손님인가"로 1:1 대응됩니다.
바뀜 (표현/납품)SalesCounterUI(티켓 카드 목록)를 걷어내고, 슬롯마다 실제 3D 손님 캐릭터가 카운터 앞 대기 자리로 걸어와 서고, 머리 위에 주문 말풍선이 뜹니다. 말풍선을 탭하면 납품(기존 티켓 탭과 동일한 TryFulfill(slotIndex) 호출).

2. 손님 캐릭터 - 지금 미술 수준에 맞춘 플레이스홀더

제대로 된 캐릭터 모델/애니메이션은 범위 밖입니다(플레이어도 지금 캡슐+구체 조합입니다). 손님도 같은 수준으로 캡슐 몸통 + 색상 변주로 만들어서 "여러 손님이 오간다"는 구분만 되게 합니다. 걷기는 애니메이션 없이 목표 지점으로 MoveTowards하는 정도, 경로탐색(NavMesh)도 필요 없는 짧은 직선 이동입니다(카운터 앞은 장애물이 없는 평지).

Superior+
Rough+
-> 대기 -> 카운터

스폰 지점에서 등장 -> 대기 슬롯으로 걸어와 정지 -> 납품/시간초과 시 같은 경로로 되돌아가며 사라짐

3. 배치 - 판매대 기준 로컬 좌표 (함수적 배치만, 장식 없음)

대기 슬롯 3곳SalesCounter 로컬 기준 (-1.4,0,-2), (0,0,-2), (1.4,0,-2) - 카운터를 바라보고 나란히 서는 자리. OrderQueueManager.slotCount와 1:1 대응(인덱스 순서 동일).
스폰/퇴장 지점로컬 (0,0,-5) 한 곳 - 여기서 나타나 슬롯으로 걸어오고, 퇴장할 때도 같은 지점으로 걸어가 사라짐. 두 방향(왼쪽/오른쪽 출입) 같은 연출적 디테일은 이번 범위 밖.
말풍선손님 머리 위(로컬 y+2.0) World Space Canvas - 등급 칩 + 인내심 바. 카메라를 향해 항상 정면을 보도록 빌보드 처리(로직만, 장식적 애니메이션 없음).

지형 높이는 Terrain.SampleHeight로 계산해서 배치(눈대중 배치 금지 원칙 유지) - 판매대 주변은 이미 평지로 확인됨.

4. 납품 흐름

슬롯에 주문 생성
(기존과 동일)
→
손님 스폰 ->
대기 슬롯으로 이동
→
말풍선 탭
= 기존 티켓 탭
→
납품/시간초과 시
퇴장 이동 -> 삭제

플레이어가 판매대에서 멀어지면(OrderQueueManager.PlayerNear == false) 손님도 전부 숨김 처리 - 시뮬레이션 자체가 그동안 멈춰있으므로(v1부터의 기존 동작) 돌아왔을 때 그대로 이어집니다.

5. 골드/평판 표시 이동

티켓 패널이 없어지면서 거기 있던 골드/평판 표시도 갈 곳이 필요합니다 - 화면 우측 상단 ResourceHUD(재료 목록)에 나머지 재화들과 같이 합칩니다. 러시아워 표시는 카운터 위에 작은 텍스트 하나로만 남깁니다(장식적 배너 제거).
